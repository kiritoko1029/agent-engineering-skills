# 可合入项目 AGENTS.md 的片段

以下内容供合入已有项目指令，不是安装脚本。Agent Notes 保留上游规则，日志部分可选；保留原有命令、权限与项目约束。必要规范位于 `dsh-archive-agent-notes` 技能的 `references/`，应随完整技能目录一起安装并读取。

## 开发记录与接续

恢复开发任务时，先查找最近相关 `.agents/journal/` 条目及其直接引用的活跃决策，再用当前代码和工作区差异确认状态。无需每次读完整个历史目录。

若项目启用工作日志，在完成一段实质开发、阶段性交接或结束当天工作时，按 `agent-change-journal` 记录目标、实际改动、执行过的验证、限制与下一步。使用 `.agents/journal/YYYY-MM-DD.md`，同一天追加任务小节；多人并行时可改用每任务独立文件。普通问答或无改动时无需生成空记录。

每次非平凡改动必须依据 `dsh-archive-agent-notes` 及其随包规范，在同一变更中新增或更新至少一份 `.agents/notes/` 下的 Agent Note。改变行为、架构、跨文件契约、流程或工具、测试策略、持久化或传输格式等均属非平凡改动。只有纯机械或局部编辑，且不改变行为、契约、结构、流程或决策理由时才豁免。已有记录能够承载同一决策时更新它，不创建重复记录；不补造替代方案、历史讨论或通过结果。

每份新 Note 都触发替代关系检查；在同一变更中归档符合条件的已实施记录，部分替代保留活跃记录并互相链接。未交付或部分交付的方案使用 `proposed`，落地后按规范转换为 `implemented`；改变既有决策时新建继任记录。默认分类沿用 `architecture`、`feature`、`bug-fix`、`simplification`、`process`、`testing`；变更分类集合时必须同步规范和项目已有的分类检查。

归档只适用于符合规范的已实施记录，归档过程中不修改正文、不核验或修复出链。封存后永久冻结，禁止编辑、翻译、重新排版、移动或删除；归档仅作为历史快照，不作为当前行为的权威。活跃文档的入链按规范处理。

## 验证与知识归属

根据变更影响选择项目已有的相关检查，准确报告通过、失败、跳过与未运行。相同代码和环境下已通过的检查，不因提交或汇报本身重复执行；项目明确要求的检查仍需完成。

代码及相应测试维护行为；用户文档维护使用方法；决策记录维护理由与取舍；日志维护工作进度。使用实际文件链接连接这些资料，避免复制整段内容。

这些约定和技能不扩大用户请求的范围或权限；发布、合并、远程写入和删除仍依原任务授权及运行环境约束执行。
