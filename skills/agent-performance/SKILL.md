# 先测量，再优化

围绕具体用户操作建立基线，找出可证伪的成本来源，实施小范围改动，再在相同工作负载下检验性能与正确性。

## 界定测量对象

根据任务确定用户操作、可观察完成条件、典型与尾部工作负载、资源限制和结束条件。区分组件耗时、端到端耗时与界面响应性；排除网络或模型延迟时明确说明。

阅读当前实现、生产调用方、适用仓库要求和已有基准。历史报告与旧分支是线索，不能替代当前版本的测量。优先复用现有测量设施，避免重复建立校准与报告系统。

## 写一张测量卡

| 字段 | 需要固定的内容 |
| --- | --- |
| 操作与入口 | 真实调用路径、构建方式及用户可观察的完成条件 |
| 输入 | 固定数据或生成常量、种子、规模、分布及代表性理由 |
| 环境 | 版本、运行时、平台、资源限制和并行负载 |
| 计时 | 起止点、包含的初始化、排除项、冷启动或预热状态 |
| 内存 | 基线、仍可达对象、回收策略、保留量与峰值的区别 |
| 判定 | 样本、统计量、噪声范围和已有预算或回归条件 |
| 正确性 | 必须保持的输出、顺序、错误、取消和资源语义 |

需要用户数据的工作负载特征时，只在任务允许的范围内提取聚合信息。使用合成输入，不将真实内容、身份、路径、凭据或可识别片段带入基准、日志和交付物。

## 建立可比较的基线

- 修改生产代码前运行当前实现，保存命令、版本、输入维度和原始样本。
- 选择真实执行入口与相同构建模式；不要复制算法另写一个“基准实现”。
- 冷测量使用新的进程或隔离环境，避免 fixture 提前暖缓存。
- 热测量明确保留哪些缓存与对象，并对两版使用相同条件。
- 计时终点、校验工作和保留结果一致；解析后丢弃不能与校验并保留完整结果直接比较。
- 控制可控的并行负载，重复采样到足以分辨收益和噪声，不挑选最快一次。

规模应覆盖真正独立的成本驱动，例如字节数、记录数、事件数和可见节点数。大量极小重复输入只证明该输入下的结果；选取能影响决策的少量典型和尾部场景。

## 形成并验证假设

用剖析、分阶段计时、分配样本或工作量计数定位重复工作。每个候选写明生产消费者、成本来源、预期复杂度、最小干预和必须保持的行为。

可调查的方向包括重复解析或复制、重复构建衍生状态、不合适的数据结构、过宽订阅、无界中间表示，以及当前用户操作不需要的提前工作。这些只是候选，必须由测量支持。

每次尽量改变一个因果因素，复测聚焦场景及其端到端上层路径。收益若在真实路径消失，应拒绝或重新界定方案。

## 保持正确性与资源边界

- 移除校验或复制前确认真实信任边界与数据归属。
- 缓存应有明确失效条件、容量边界、取消语义与清理所有者。
- 延迟计算应测量首次使用成本；推迟工作不等于删除成本。
- 不把正确性要求的工作移到计时终点之后来改善数字。
- 不通过截断数据、漏掉结果、忽略错误或削弱持久化语义达成目标。
- 运行与本次变更相关的功能测试，覆盖实际受影响的输出、顺序、并发、取消与清理。

界面优化需通过真实浏览器输入与最终画面更新测量响应性。组件计算或模拟 DOM 不能证明滚动、绘制和交互顺畅；明确哪些界面行为确实测过。

## 性能回归保护

需要长期性能检查时，在实际执行环境测量噪声并选择有意义的预算。优先扩展已有基准，避免为微小收益引入维护昂贵或波动很大的检查。

用旧实现或受控重引入目标成本的反例，确认检查能识别目标回归。功能断言独立于基准内部实现；性能阈值既不能宽到放过原缺陷，也不能低于已观察的噪声范围。

同时观察保留内存和适用的峰值压力。更快但无界保留、典型场景明显变慢，或增加的复杂度大于收益，都可能使优化不值得采用。

## 交付

报告工作负载、前后绝对值与比例、样本和统计量、测量终点、内存语义、功能证据及限制。分别标记历史数字、当前本地结果和 CI 结果，不将某一环境的结果推广为普遍结论。

达到任务的场景与改动范围后停止。尚未实施的假设可按证据与潜在收益简短排序，不为追求更多收益持续扩张任务。
